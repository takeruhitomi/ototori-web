# プロジェクトのバックアップ

0.1.4以降の「プロジェクトを書き出す」「バックアップを復元」。通常のJSON書き出しと違い、編集履歴と原譜を別の端末へ移せる構成。

## 操作と保存内容

楽譜画面の「プロジェクトを書き出す」でZIPを保存する。書き出す時点の楽譜・文書ID・リビジョン・Undo/Redo履歴を1つのスナップショットにする。原譜参照がある場合は元PDFを含め、アプリ内に残っている完了ページの原認識結果も含める。モデル・音源は含めない。

原譜を参照しているのに端末内にPDFがない場合は、原譜付きバックアップとして成功させずエラーを表示する。通常のJSON書き出しは利用できる。原譜参照のない既存score.jsonのプロジェクトは、楽譜と履歴だけで書き出せる。

「バックアップを復元」でZIPを選ぶ。内容を専用一時領域へ展開してサイズ・ハッシュ・原譜の対応を確認し、Dart側で楽譜と履歴を検証した後に原譜と完了ページを取り込む。ライブラリには新しい保存IDで追加し、既存の編集済み楽譜を上書きしない。文書内のID・リビジョンは保持する。復元後の編集は追加したライブラリ項目へ自動保存する。

変換ジョブ自体や未完了五線のキャッシュ、表示画像、ミキサー設定は含めない。完了ページは一致するPDF・解像度・認識名前空間で再利用できる。これらの制限は楽譜・履歴・原譜の復元とは別。

## ZIP version 1

最初の項目はUTFエスケープを扱うJava Properties形式の `manifest.properties`。formatは `choir-omr-project`、versionは1、countは本文ファイル数。entry.N.name / bytes / sha256で各本文の名前・展開後サイズ・SHA-256を指定する。recognition_namespaceは現在 `symbols-v1-396-308`。原認識結果を含む場合は、対応する名前空間を必須とする。

本文で認める名前は以下のみ。

- `project.json`: PROJECT_FORMAT.mdのアプリ内楽譜。
- `source.pdf`: project.jsonのmeta.source_hashにSHA-256が一致するPDF。原譜参照のあるプロジェクトで必須。
- `recognition/300/N.bin` / `recognition/400/N.bin`: 完了ページの原認識結果。Nは0から始まるページ番号。Flutter StandardMessageCodec形式で、RecognitionCacheのページ形式も検証する。

本文の展開後合計は1GiB、project.jsonは10,000,000 bytes、原認識結果は1ファイル64MiB、本文は最大2002項目に制限する。これは対応最低RAMや通常の推奨容量を示す値ではない。本文全体をメモリに載せずにコピーとハッシュ計算を行う。

不足・重複・未宣言の本文、不正なパス、サイズ・ハッシュ不一致は拒否する。ZIP内の名前からアプリの保存場所を選ばせず、検証後にアプリ側で保存先を決める。原譜はPDFとしても開けることを取り込み時に確認する。復元で途中失敗した場合、既存ライブラリは上書きしない。読み込み済みの原譜や再生成可能なページキャッシュだけが残る場合はある。

書き出しはアプリの一時領域でZIPを完成してからAndroidの保存先選択を開く。外部ストレージへのコピーが失敗した場合は成功表示しない。選択先ファイルの置換の原子性は保存プロバイダーによる。一時ZIPと通常の失敗・キャンセル時の展開ファイルは削除する。アプリプロセス自体の終了時に一時ファイルが残る可能性はある。

## 検証状況

JVMテストでZIPのバイト往復、パス・重複・未宣言項目・欠落・サイズ超過・ハッシュ不一致・認識名前空間不一致の拒否を確認した。実際のStandardMessageCodec形式の原認識結果も読み戻して検証した。Dartでは不正履歴をネイティブ取り込み前に拒否し、正常復元・キャンセル・画面破棄・ネイティブ失敗・復元後の自動保存を検証した。

Androidの保存先選択、実際のPDFを含む書き出し・別端末での復元・再起動後の原譜表示は未検証。単体テストと画面の模擬境界テストを、これらの実行時確認の代替にはしない。
